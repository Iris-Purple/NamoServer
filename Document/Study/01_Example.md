## 스레드(Thread)란?

**스레드는 프로그램 내에서 실행되는 독립적인 작업 단위**입니다. 하나의 프로세스 안에서 여러 스레드가 동시에 실행될 수 있습니다.

### 비유로 이해하기

레스토랑을 예로 들어보겠습니다:

- **프로세스** = 레스토랑 전체
- **스레드** = 각 직원 (웨이터, 요리사, 계산담당 등)
- **공유 자원** = 주방, POS 시스템, 재료 창고

여러 직원(스레드)이 동시에 일하면서 레스토랑(프로세스)을 운영합니다.

# C++ ThreadManager 구현 및 분석

## 📌 개요

게임 서버에서 멀티스레드를 효율적으로 관리하기 위한 ThreadManager 클래스 구현

## 🎯 핵심 개념

### 1. Thread Local Storage (TLS)

```cpp
thread_local uint32 LThreadId = 0;
```

- **thread_local**: 각 스레드마다 독립적인 변수 인스턴스를 가짐
- 스레드별 고유 ID를 저장하여 디버깅 및 로깅에 활용
- 전역 변수처럼 보이지만 실제로는 각 스레드가 자신만의 복사본을 가짐

### 2. 스레드 ID 생성 메커니즘

```cpp
void ThreadManager::InitTLS()
{
    static atomic<uint32> SThreadId = 1;
    LThreadId = SThreadId.fetch_add(1);
}
```

- **static atomic<uint32>**: 모든 스레드가 공유하는 원자적 카운터
- **fetch_add(1)**: 원자적으로 값을 가져오고 1 증가 (thread-safe)
- 각 스레드는 고유한 순차 ID를 보장받음

## 🔧 주요 컴포넌트 분석

### ThreadManager 클래스 구조

### 멤버 변수

```cpp
private:
    mutex _lock;           *// 스레드 벡터 보호용 뮤텍스*
    vector<thread> _threads;  *// 관리중인 스레드들*
```

### Launch 함수 - 스레드 생성 및 실행

```cpp
void ThreadManager::Launch(function<void(void)> callback)
{
    lock_guard<mutex> guard(_lock);  *// RAII 패턴으로 자동 락 해제*
    
    _threads.push_back(thread([=]()  *// 값 캡처로 callback 복사*
    {
        InitTLS();      *// 스레드 시작시 TLS 초기화*
        callback();     *// 실제 작업 수행*
        DestroyTLS();   *// 스레드 종료시 정리*
    }));
}
```

**핵심 포인트:**

1. **lock_guard 사용**: RAII 패턴으로 예외 안전성 보장
2. **람다 캡처 [=]**: callback을 값으로 캡처 (안전한 복사)
3. **생명주기 관리**: InitTLS → callback → DestroyTLS 순서 보장

### Join 함수 - 모든 스레드 대기

```cpp
void ThreadManager::Join()
{
    for (std::thread& t : _threads)
    {
        if (t.joinable())  *// join 가능 여부 확인*
            t.join();       *// 스레드 종료 대기*
    }
    _threads.clear();
}
```

## 💡 설계 패턴 및 장점

### 1. RAII (Resource Acquisition Is Initialization)

- 생성자에서 InitTLS() 호출
- 소멸자에서 Join() 호출로 자동 정리
- 예외 안전성 보장

### 2. Thread Pool 패턴의 기초

- 여러 스레드를 중앙에서 관리
- 일괄 생성 및 종료 가능

### 3. TLS를 통한 스레드 식별

- 전역 변수 사용 없이 스레드별 상태 관리
- 디버깅 시 스레드 추적 용이

# ThreadManager를 사용하는 이유

## 🎯 핵심 목적

**멀티스레드 프로그램의 복잡성을 줄이고 안전성을 높이기 위함**

## 1. 스레드 생명주기 관리

### 문제 상황

- 프로그램 종료 시 실행 중인 스레드를 깜빡하면 크래시 발생
- 각 스레드의 join()을 개별적으로 호출해야 함
- 스레드가 10개면 10번의 join() 호출 필요

### ThreadManager의 해결

- 모든 스레드를 vector에 저장하여 일괄 관리
- 소멸자에서 자동으로 모든 스레드 종료 대기
- 깜빡할 수 없는 구조로 안전성 보장

## 2. 스레드 식별 및 디버깅

### 문제 상황

- 멀티스레드 환경에서 로그만 보고는 어떤 스레드의 동작인지 알 수 없음
- 데드락이나 성능 문제 발생 시 원인 스레드 찾기 어려움
- 스레드별 통계나 모니터링 불가능

### ThreadManager의 해결

- 각 스레드에 고유 ID 자동 부여 (thread_local 변수 활용)
- 모든 로그에 스레드 ID 포함 가능
- 문제 발생 시 특정 스레드 즉시 식별

## 3. 일관된 초기화 및 정리

### 문제 상황

- 각 스레드마다 필요한 초기 설정이 있음 (TLS, 메모리 풀, 로거 등)
- 개발자가 매번 수동으로 설정하면 실수 가능성
- 스레드 종료 시 리소스 정리 누락 위험

### ThreadManager의 해결

- Launch 함수 내부에서 자동으로 InitTLS() 호출
- 스레드 종료 전 DestroyTLS()로 정리 보장
- 모든 스레드가 동일한 초기화 과정 거침

## 4. 중앙 집중식 관리의 장점

### 관리 포인트 단일화

- 스레드 관련 코드가 한 곳에 집중
- 스레드 개수 변경 시 한 곳만 수정
- 스레드 정책 변경 시 ThreadManager만 수정하면 됨

### 리소스 관리

- 생성된 모든 스레드를 추적 가능
- 메모리 누수나 좀비 스레드 방지
- 프로그램 종료 시 확실한 정리

## 5. 실제 게임 서버에서의 필요성

### 게임 서버 특성

- 네트워크 I/O, 게임 로직, DB 처리 등 다양한 작업 동시 수행
- 각 작업마다 전용 스레드 필요
- 동시 접속자 수에 따라 워커 스레드 수 조절 필요

### ThreadManager 없이 개발하면

- 스레드 생성/종료 코드가 여기저기 산재
- 서버 종료 시 일부 스레드가 작업 중일 수 있음
- 스레드 관련 버그 발생 시 디버깅 매우 어려움

### ThreadManager 활용 시

- 서버 시작: 필요한 모든 스레드 일괄 생성
- 서버 운영: 각 스레드 상태 모니터링 가능
- 서버 종료: 모든 스레드 안전하게 종료 보장

## 6. 확장성과 유지보수

### 요구사항 변경 대응

- "워커 스레드를 5개에서 10개로 늘려달라" → 숫자 하나만 변경
- "스레드별 우선순위 설정 추가" → ThreadManager에만 기능 추가
- "스레드 성능 모니터링 추가" → Launch 함수에 코드 추가로 해결

### 코드 품질

- 스레드 관련 로직이 캡슐화되어 있음
- 다른 개발자도 쉽게 이해하고 사용 가능
- 테스트와 디버깅이 용이함

## 📌 결론

**ThreadManager는 선택이 아닌 필수**

멀티스레드 프로그램, 특히 게임 서버처럼 복잡한 시스템에서는 스레드 관리를 체계화하지 않으면 유지보수가 불가능해집니다. ThreadManager는 이러한 복잡성을 관리 가능한 수준으로 낮춰주는 필수 컴포넌트입니다.

주요 이점:

- **안전성**: 모든 스레드의 확실한 종료 보장
- **추적성**: 각 스레드 식별 및 디버깅 가능
- **일관성**: 모든 스레드가 동일한 초기화/정리 과정
- **유지보수성**: 스레드 관련 코드 중앙 집중
- **확장성**: 스레드 수나 정책 변경 용이

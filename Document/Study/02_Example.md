### 1단계: 단일 스레드 실행

```cpp
Add();  *// sum을 100만 번 증가*
Sub();  *// sum을 100만 번 감소*
cout << sum << endl;  *// 결과: 0*
```

- 순차적으로 실행되어 `sum`이 100만 증가 후 100만 감소
- **결과는 항상 0**

### 2단계: 멀티스레드 실행

```cpp
std::thread t1(Add);  *// 스레드1: sum을 100만 번 증가*
std::thread t2(Sub);  *// 스레드2: sum을 100만 번 감소*
t1.join();
t2.join();
cout << sum << endl;  *// 결과: ???*
```

- 두 스레드가 **동시에** `sum`을 수정
- **결과는 예측 불가능!** (0이 아닐 가능성이 높음)

## 왜 문제가 발생하는가?

`sum++`이나 `sum--`는 실제로 3단계로 이루어집니다:

```cpp
*// sum++의 실제 동작*
1. temp = sum;      *// 메모리에서 값 읽기*
2. temp = temp + 1; *// 계산*
3. sum = temp;      *// 메모리에 쓰기*
```

### 동시 실행 시 발생하는 문제:
```
시간 →
Thread1: [읽기:0] → [계산:1] → [쓰기:1]
Thread2:      [읽기:0] → [계산:-1] → [쓰기:-1]

결과: sum = -1 (1이 될 수도, -1이 될 수도 있음)
```

두 스레드가 같은 값을 읽고 각자 계산한 후 덮어쓰기 때문에 **Race Condition** 발생!

## 해결 방법: atomic 사용

```cpp
#include <atomic>

std::atomic<int32> sum(0);  *// atomic으로 선언*

void Add()
{
    for (int32 i = 0; i < 1000000; i++)
    {
        sum++;  *// 원자적 연산으로 실행됨*
    }
}
```

`atomic`을 사용하면:

- `sum++`가 **원자적(atomic) 연산**으로 실행
- 읽기-수정-쓰기가 **하나의 분리 불가능한 연산**으로 처리
- 다른 스레드가 중간에 끼어들 수 없음

## 실행 결과 예상

```cpp
*// atomic 없이*
첫 번째 출력: 0 (항상)
두 번째 출력: -123456, 98765, 0, ... (매번 다름)

*// atomic 사용 시*
첫 번째 출력: 0 (항상)
두 번째 출력: 0 (항상)
```

## 핵심 개념 정리

1. **Race Condition**: 여러 스레드가 동시에 같은 데이터를 수정할 때 발생
2. **atomic**: 연산을 원자적으로 만들어 동시성 문제 해결
3. **join()**: 스레드가 끝날 때까지 대기
